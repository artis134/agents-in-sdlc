GitHub Copilot をエージェント モードで使うと、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムに確認できます。差分を確認して個別の変更を採用または取り消したり、追加のプロンプトを送って作業を調整・拡張したりできます。すべてエディター内で行えます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして採用します。
- セッションの途中で指示を追加し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中にデザイン チームから、既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加してほしいという依頼がありました。新しい会話を始めるのではなく、既存のセッションに指示を追加します。

## Copilot の進捗を監視する

Copilot Chat ビューでは、エージェントが調査したファイル、実行したコマンド、提案した編集を確認できます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの操作を確認します。ファイルの読み込みや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルを編集すると、差分がチャットに表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を取り消し、エージェントに再度作業してもらいます。
4. チャット上部の **Files changed** の表示を開くと、このセッション中にエージェントが変更したすべてのファイルを確認できます。

> [!NOTE]
> ターミナル コマンドの実行などで許可が必要な場合、エージェントは停止して **Allow** を表示します。許可するのは、内容を確認して実行してもよいコマンドだけにしてください。

5. エージェントがハイ コントラスト モードを実装し終えるまで待ちます。最後に、変更内容の要約が表示されます。

## ライト モードを追加するようエージェントを案内する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えも追加します。会話を続けることで、エージェントは前の作業で変更したコンポーネント、スタイルの方針、ローカル ストレージの利用方法を保持します。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントはこれまでの変更を調べ、ライト モードの追加を提案します。
3. 変更ごとに差分を確認し、**Keep** または **Undo** を選択します。
4. 望まない方向に進んだ場合 (たとえば、好みと異なる方法で切り替え UI を再構成しようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、補足のプロンプトを送ります。

> [!TIP]
> 進行中のセッションに指示を追加すると、最初からやり直すより短時間で調整できます。たとえば、「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使用する」、「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合する」、「両方の切り替えにキーボード ショートカットも追加する」といった追加の指示を送れます。

## 作業内容をレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが指示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージへの保存) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルで変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視し、各ファイルの編集を確認して採用または取り消し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、次のことを学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々の編集を採用または取り消す。
- 追加プロンプトで進行中のセッションを案内する。

次の[レッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通じてローカルのカスタム エージェントが作成した変更をレビューします。
